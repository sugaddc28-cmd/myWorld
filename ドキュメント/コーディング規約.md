# コーディング規約

このプロジェクトで合意したコードの書き方をまとめる。コードの作成・修正・提案時に参照する。
開発全体の進め方とUdonSharpの作成手順は [開発方針](開発方針.md) を参照。

## アクセス修飾子とフィールド

- クラス内のフィールド・メソッド・プロパティは、既定のアクセスがprivateになるため、`private` を明記しない。コード例や差分でも同じ書き方にする。
- `public` や `protected` など、必要なアクセス修飾子は明記する。省略で意味が変わる箇所まで機械的に削除しない。例えばpublicプロパティの `private set` は別途判断する。
- Inspectorで調整する値は、外部公開が不要なら `[SerializeField] float minPointDistance = 0.005f;` のように書く。
- フィールドは設定・状態・参照など役割ごとにまとめ、空行で区切る。保存用フィールドと対応するプロパティは隣に置く。

## プロパティと参照の取得

- 固定したオブジェクト構成から取得できる参照は、原則としてプロパティで必要時に取得し、非公開フィールドへ保持する。参照の初期化を理由なく `Start()` に分散させない。
- 保存用フィールドは `_line`、プロパティは `Line` のように命名する。利用側はプロパティ経由で参照する。
- 単純な取得・保持には `_line = _line ?? GetComponentInChildren<LineRenderer>();` の形を使える。
- 初回取得時の設定も行う場合は、取得済みなら先に返し、取得失敗時も返す。初期設定を深いネストや `else` の中へ埋め込まない。
- `??` はUnityオブジェクトの破棄済み判定の代用にはしない。途中で破棄・再生成する参照は、そのライフサイクルに合う有効性確認を行う。
- UdonSharpを前提に構文・APIを選ぶ。`??=` や `field` などは対応を確認せずに採用しない。

## 必須参照の取得失敗

- 取得失敗はプロパティ内で `Debug.LogError()` を出す。メッセージには、足りないものと修正方法を書く。
- 現在のペンのように構成が固定された必須参照は、呼び出し側では存在を前提に使い、同じ参照への防御的なnullチェックや無言の `return` を重ねない。設定ミスはエラーとして発見し、構成を直す。
- `Debug.LogError()` 自体は処理を中断しない。この方針では、取得失敗後のアクセスで実行時エラーになり得ることを前提とする。
- 正常な状態として参照が存在しない場合や、外部入力・動的な破棄がある場合は、必要なnullチェックを行う。
- ログの重複抑制フラグは一律に追加せず、まず単純に書く。連続して呼ばれる箇所でログが問題になった場合に対処する。

## 初回取得と初期設定の例

Penの子のStrokeにLineRendererが付いている前提。非アクティブな子も検索する。

```csharp
LineRenderer _line;

LineRenderer Line
{
    get
    {
        if (_line != null) return _line;

        _line = GetComponentInChildren<LineRenderer>(true);

        if (_line == null)
        {
            Debug.LogError(
                "[PenInput] 子にLineRendererが見つかりません。"
                + "Penの子のStrokeにLineRendererを追加してください。");

            return null;
        }

        _line.useWorldSpace = true;
        _line.loop = false;

        return _line;
    }
}
```
